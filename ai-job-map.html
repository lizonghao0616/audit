03 · Transition Paths

转岗路径清单

8 条路径按可行性排序，每条都给出「第一步行动」——可行性 = 技能可迁移度 × 岗位缺口。

后端 / 全栈 → 大模型应用 / Agent 开发
★★★★★
迁移点：编程、工程、API、数据库、部署全都有
需补齐：LLM 原理 + RAG/Agent + Prompt + 框架
周期：3–6 个月
第一步：复现 1 个 RAG 知识库 demo + 1 个 Agent demo，开源到 GitHub
避坑：别只刷 LangChain 教程——面试看的是「能跑通、能讲清架构」的项目，不是课程证书。
产品经理 → AI 产品经理
★★★★★
迁移点：需求、PRD、竞品、数据分析
需补齐：大模型能力边界 + Prompt
周期：2–3 个月
第一步：写 1 份大模型产品 PRD + 用 Coze 搭 1 个智能体
避坑：别把 Prompt 当「万能话术」——核心竞争力是能说清模型能力的边界与失败场景。
前端 / 客户端 → AI 应用开发
★★★★☆
迁移点：交互、组件、工程化
需补齐：Python + API 调用 + Agent 编排
周期：3–6 个月
第一步：做 1 个接入 Agent 的对话式前端作品
避坑：别纠结「要不要补算法」——先用 Python 把 API 调用 + 流式输出跑通，算法不是入场券。
运营 / 市场 → AI 运营
★★★★☆
迁移点：数据指标、内容、用户、项目推进
需补齐：模型路由/成本 + Prompt 调优
周期：2–3 个月
第一步：拆解 1 个模型的用量/成本指标，写 Prompt 调优复盘
避坑：别停留在「会用 AI 工具」——能算清单次调用的成本和 ROI，才是运营岗的护城河。
销售 / 售前 → AI 售前 / 解决方案
★★★★☆
迁移点：行业理解、沟通、方案、PPT
需补齐：技术方案边界 + 落地案例
周期：2–3 个月
第一步：梳理 1 个行业的 AI 落地方案 PPT + 3 个案例
避坑：别把「AI 什么都能干」讲成吹牛——能给出能力边界和真实案例的售前才值钱。
测试 / QA → AI Agent 开发（评测）
★★★★☆
迁移点：用例设计、质量意识、自动化
需补齐：大模型评测体系 + Benchmark
周期：2–4 个月
第一步：给 1 个 Agent 写评测用例集 + 自动化脚本
避坑：别只做「能跑通」的一次性测试——可复用的评测集 + 指标，才是你的差异化作品。
数据分析 → 数据工程 / 评测
★★★☆☆
迁移点：SQL、Python、统计
需补齐：数据管道 + 向量库 + 评测集
周期：3–6 个月
第一步：构建 1 个评测数据集 + 跑通评测流程
避坑：别只在 SQL 上原地打转——向量库 + 评测流程，才是转岗后的新增量。
零基础 / 文科 → Prompt 工程师 → 进阶
★★★☆☆
迁移点：语言表达、逻辑、领域知识
需补齐：Prompt 范式 + AI 工具 + 作品集
周期：30 天起步
第一步：30 天实操攒作品集（作品集比简历更重要）
避坑：别背提示词模板——面试官看的是「同一需求下你如何迭代出更好结果」的思考过程。
04 · 30-Day Plan

30 天起步清单

不管走哪条路径，前 4 周都能落地的动作。

WEEK 1

定岗 + 摸 JD

选定 1 个目标岗位，扒 10 条真实 JD 提炼共同要求，注册 Dify / Coze 搭出第一个智能体。

WEEK 2

补 1 个核心技能

技术岗补 Python，非技术岗补 Prompt 范式。复现 1 个 RAG demo 或写 10 组高质量 Prompt。

WEEK 3

做一个完整作品

做 1 个能演示的 Agent 小项目（知识库问答 / 自动摘要 / 客服），并写复盘文档。

WEEK 4

作品集 + 投递

打磨作品集（附链接），改写简历突出「项目 + 数据」，投递时把作品链接贴进简历。

05 · Why It Works

为什么「转岗可行」

不是画饼，三条判断依据。

看作品，不唯学历

大量 JD 把「项目经验 / 作品集 / GitHub 开源」列为优先项，甚至高于学历。一个能跑起来的 Agent 比一纸证书更有说服力。

原行业 = 差异化优势

AI 落地难在「懂业务」而非「懂算法」。转岗者带着原行业理解入场，正是复合型人才的溢价来源。

工具门槛已大幅降低

Dify、Coze 等低代码平台让「不写代码也能搭 Agent」成为可能，入行不再需要先啃完深度学习和高数。
